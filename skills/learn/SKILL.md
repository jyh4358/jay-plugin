# /learn — 새로 알게 된 것 기록

record가 "무엇을 했다"라면 이것은 "무엇을 알게 됐다"를 남긴다. 용도는 이력서가 아니라 '나를 아는 LLM'의 지식 베이스다: 몰랐던 것, 잘못 알고 있던 것, 직접 해봐야 알 수 있었던 것.

## 0. 설정

1. `~/.claude/record-config.json`에서 vaultPath를 읽는다 (record 스킬과 공유). 없으면 vault 경로를 물어 `{ "vaultPath": "<절대 경로>" }`로 생성한다 — record가 쓰는 다른 키(defaultOrg)는 그 스킬이 필요할 때 채운다.
2. vault 검증: `99-템플릿/Worklog.md` 존재 확인 (올바른 vault인지 표식 검사).
3. `99-템플릿/Learning.md`가 없으면 §3의 템플릿 전문을 그대로 담아 생성한다. `30-학습/` 폴더도 없으면 만든다.
4. vault가 git 저장소면 시작 전 `git pull`.
5. 날짜는 bash(`date +%F`)로 얻는다 — 암산 금지.

## 1. 학습 단위 식별

- 기록 대상 = 세션에서 새로 알게 된 것 하나. 여러 개면 학습 1개 = 노트 1개.
- 사용자가 특정하지 않고 "이번 세션에서 배운 것 기록해줘"라고 하면 후보를 나열해 고르게 한다.
- 세션 맥락 없이 주제를 직접 지정받으면(예: "이 개념 정리해서 남겨줘") 같은 절차로 진행한다. 이때 모델 지식으로 내용을 보강해도 되며, 세션에서 실제 겪은 것이 있으면 그것을 우선한다.
- **'왜/원리'가 유일한 내용 요건이다**: 왜 그렇게 동작하는지, 왜 그 방법이 나은지가 빠져 있으면 한 번 물어 채운다. 그래도 안 나오면 저장하지 않는다 — 사실 나열만 남는 노트는 스크랩과 다를 게 없다.

## 2. 기존 노트 확인 — 중복 생성 금지

초안을 쓰기 전에 같은 주제의 기존 학습 노트가 있는지 `30-학습/`을 제목·summary·tech로 Grep한다. **있으면 새 노트 대신 그 노트를 보강하는 방향으로 초안을 잡는다** — Read 후 Edit 부분 수정 + `updated` 갱신 (통째 덮어쓰기 금지, `date`는 최초 학습일이므로 유지).

## 3. 노트 형식 — frontmatter 고정, 본문 자유

`99-템플릿/Learning.md`의 전문. §0에서 템플릿을 생성할 때 이 내용을 그대로 쓴다:

```markdown
---
summary:
type: learning
tech: []
tags: []
date:
updated:
---
# (배운 것 제목)

본문 양식 자유 — 개념 정리, 전후 비교, 삽질 인사이트 등 내용에 맞는 모양으로. 단 '왜/원리'는 반드시 담는다.

관련: [[ ]]
```

- 필드 규칙: summary = 배운 것 한 문장 / tech = 고유명사 원어 / tags = 선택, tech와 겹치는 값은 넣지 않는다 / date = 배운 날(빈 값 금지, bash로) / updated = 수정할 때마다 갱신.
- 본문 양식은 정하지 않는다 — 내용에 맞는 모양으로 쓰되 '왜/원리'는 반드시 담는다(§1).
- vault에 관련 노트(같은 tech·주제의 학습 노트, 기존 worklog)가 이미 있으면 본문 말미에 `관련: [[...]]` 한 줄로 링크하고, 없으면 그 줄을 뺀다 — 억지로 잇지 않는다. 이번 세션의 worklog는 보통 아직 없다: 그 방향 연결은 세션 말미에 record 스킬이 잇는다.

## 4. 검증 — 틀린 지식은 수정하여 기록한다

저장 전에 노트의 **일반 원리 주장**('왜/원리'에 해당하는 부분)이 맞는지 판단한다. 불확실하거나, 버전 의존적이거나, 모델 지식으로 보강한 내용이면 검색해 확인한다. 인용은 그 기술의 **1차 출처만** — 해당 기술을 만든 조직·프로젝트가 직접 운영하는 공식 문서·스펙·소스 저장소. 사전 목록은 없다, 건별로 이 기준으로 판단한다. 검증에 사용한 링크는 본문에 남긴다.

- 직접 관측한 경험적 사실은 검증 대상이 아니다 — 전제(환경·조건)와 함께 관측으로 기록한다.
- 검증 결과가 세션의 결론과 **모순되면 그게 진짜 학습이다**: 사용자에게 알리고, 교정된 내용으로 기록하되 **세션에서 무엇을 어떻게 잘못 알고 있었는지 본문에 명시한다**.
- 2차 출처(블로그 등)는 판단 참고로만 쓰고 노트에 링크로 남기지 않는다 — 링크는 나중에 권위로 재서빙된다.
- 확인 불가하면(1차 출처를 못 찾은 경우 포함) 추정임을 명시하고 저장한다. 검색이 불가능한 환경이면 미검증 표시 후 진행한다.

## 5. 일반화 — 출처 불문 항상 적용

학습 노트에는 org 구분이 없으므로 회사·개인 출처를 가리지 않고 일관 적용한다. 지식만 남기고 맥락 특정 정보는 치환한다:

- 실제 테이블·컬럼명, 스키마 상세, 데이터 값 → 일반명·예시값
- 미공개 사업 지표 절대값 → 상대값 ("3배", "40% 감소")
- 고객·개인 정보, 크리덴셜, 내부 URL·IP·호스트명, 회사 소스코드 원문 → 제거 (해결 접근·의사코드 수준까지만)

치환이 애매한 항목이 있으면 **그 항목만 ⚠️로 개별 확인**받는다. 없으면 확인 없이 바로 저장한다 — 세션 흐름을 끊지 않는 것이 이 스킬의 존재 이유 중 하나다.

## 6. 저장

1. 신규 노트는 `30-학습/<제목>.md`. 제목은 내용이 드러나는 구체적 문구, 날짜 prefix 없음. 동명 충돌 시 괄호 보조.
2. 저장 후 파일 경로와 summary 한 줄, 신규/보강 여부를 보고한다.
3. vault가 git 저장소면 커밋·push 여부를 물어 진행한다. git 미사용 상태면 생략.
4. 이 지시문 내용을 노트에 옮겨 적지 않는다.
